Hazards · where to look first

The cold start is the weak spot. Start there.

  • ■ Risk

    Cold start can stampede Postgres

    After a deploy every key is cold, so every read misses at once. Request coalescing sends one query per key while the other reads wait for it.

  • ○ Check

    A missed delete serves stale data for up to 5 minutes

    If a write path forgets to delete its key, readers see the old row. The 5-minute TTL bounds how long.

  • ▲ Later

    Hit rate is a 7-day average

    One busy endpoint can hide a cold one. Measure the hit rate per endpoint.

Kill switch

cache.enabled=false sends every read to Postgres. p95 returns to about 840 ms.

05

What to remember

Read from memory, write to the source.

  1. One.

    Cache what repeats.

    Dashboard reads repeat, so 94 of every 100 come from Redis in about 3 ms.

  2. Two.

    Delete on write.

    The API deletes the key after a write. The next read refills it from Postgres.

  3. Three.

    The TTL is the safety net.

    If a delete is missed, the 5-minute TTL caps how long stale data lives.
