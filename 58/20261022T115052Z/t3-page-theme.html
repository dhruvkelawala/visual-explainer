Field noteThesis

In T3, a page cannot ask the system for light or dark. It reads T3’s background and takes the scheme whose text has more contrast on it.

00
The one idea

Ask the thread, not the system.

Each block below does one job in that rule: T3 supplies the colour, contrast reads it, and a switch reads it again.

01
Block 1 · Theme variables

T3 hands the page its colours before the page runs.

We switched T3 to dark. Why did the old page stay bone-white?

T3 shows a page inside a frame. Before the page’s own code runs, T3 adds a style named #t3-theme at the top of <head>. It sets --background, --foreground and about forty more variables on :root.

Inside the frame, the media query prefers-color-scheme does not follow T3. It reads light in both of T3’s modes, so a page that asks it draws a light ground on a dark thread.

In our project

The first <head> script in templates/field-guide.html looks for #t3-theme. When it finds it, it adds the t3 class, and the T3 VISUAL PAGE CSS block drops the bone ground, hides the Light/Dark switch and lines the left edge up with the reply text.

test/field-guide-t3.test.mjs injects the same style T3 does, with T3’s base sheet copied from the app.

02
Block 2 · Contrast

Contrast, not a name, picks the scheme.

T3’s background could be any colour. How dark is dark enough?

Relative luminance says how bright a colour looks, from 0 for black to 1 for white. The contrast ratio of two colours is (L1 + 0.05) / (L2 + 0.05). Both come from the Web Content Accessibility Guidelines (WCAG).

White text and black text have equal contrast on a ground with luminance 0.179. Below it, white text wins, so the page turns dark. Above it, black text wins, so the page stays light.

In our project

The head script paints --background onto a one-pixel canvas and reads the pixel back. The canvas turns any CSS colour, hex, rgb() or oklch(), into the same sRGB numbers, so one formula covers every T3 theme.

The tests check #0a0a0a and oklch(0.25 0.02 260) turn dark and #fcfcfc turns light.

■ Watch out

A custom T3 theme with a mid-grey background can come out on the side its name does not suggest. A colour the canvas cannot read leaves the pixel white, so the page falls back to light.

03
Block 3 · Live switch

A theme switch picks again in place.

The reader switches T3 to light while the page is open. Does the page follow?

T3 does not reload the page. It sends the frame a host-context-changed message, and its own script rewrites the text of #t3-theme with the new colours.

The head script watches that style with a MutationObserver, which calls back when the style’s text changes. It measures the new background and sets data-theme again, so the Field Guide tokens flip with no reload.

In our project

The test turns light when the reader switches T3 to light rewrites #t3-theme the way T3 does and checks that the page’s text and plate colours become the light tokens.

Cheat sheet

Seven terms carry this page.

T3 visual page
A page shown in a T3 thread through html_render, on the thread’s own background.
#t3-theme
The style T3 adds at the top of the page’s head, holding its colours as CSS variables.
--background
T3’s variable for the thread’s background colour.
prefers-color-scheme
The media query for the system’s light or dark mode; it does not follow T3 inside the frame.
relative luminance
How bright a colour looks, from 0 for black to 1 for white.
MutationObserver
A browser object that calls back when the nodes it watches change.
data-theme
The attribute on <html> that switches the Field Guide tokens between light and dark.
